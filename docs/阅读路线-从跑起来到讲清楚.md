# 阅读路线：从跑起来到讲清楚

> 目标：4 天、约 12 小时，把 4 个页面、14 个接口、26 件商品装进脑子。
> 适合：已学 HTML/CSS、JS 的 DOM/事件/fetch/Promise/ES 模块、Node 基础。
> 用法：每完成一站再进下一站；每一站的“过关标准”能答出来，才算读完。

## 先记住三件事

1. **先跑后读**：先当用户完整走一遍，再看代码怎么实现。
2. **一次只追一条请求**：读后端只追 `GET /api/products`，读前端只追首页加载。
3. **每个文件只回答三个问题**：输入是什么、输出是什么、它依赖谁。

## 总路线

| 站 | 时间 | 目标 | 主要文件 | 过关标准 |
| --- | --- | --- | --- | --- |

## 第 0 站：当半小时用户（30 min）

先不打开代码。启动服务（`npm start`，或双击根目录的 `启动商城.bat`），把下面这条路径走一遍，每一步都留意页面变了什么：

1. 搜索“耳机”，记下结果数量。
2. 点分类“数码”，再点价格“¥100–299”，看结果和地址栏一起变。
3. 点进“听风 Studio 头戴降噪耳机”，把数量改成 2，加入购物车。
4. 打开右侧抽屉，改数量、删一项、再重新加。
5. 去结算，先故意把手机号填错，看提示；改对后提交。
6. 在结果页复制订单号，刷新页面，再去“我的订单”看历史单。

打开 F12 的 Network，勾上 Preserve log，把每个请求的 Method、路径、状态码记在纸上。

**过关标准**：不看页面，能画出“首页 → 详情 → 购物车抽屉 → 结算弹窗 → 订单结果 → 我的订单”这张图。

## 第 1 站：地图与契约（60 min）

这一站只建立词汇表，不读实现。

1. `README.md`：项目介绍、启动方式、考核点对照、目录树。
2. 每个文件夹里的 `说明-这个文件夹装什么.md`：只读“一句话”和“装了什么”。
3. `docs/小满商城-文件说明书.pdf` 第 1–3 节：项目速览、目录地图、一次请求怎么走。
4. `docs/接口文档-前后端约定.md`：只精读四段——统一信封、错误码表、`GET /api/products`、`POST /api/orders`。

**过关标准**：能说出 14 个接口分成商品 5 个、购物车 5 个、订单 4 个；能解释 `{ code, message, data }` 三个字段各自的意义。

## 第 2 站：后端读链路（90 min）

目标请求：`GET /api/products?keyword=耳机&category=数码&minPrice=100&maxPrice=299&sort=price-asc&page=1&pageSize=8`

按这个顺序读，一层只读一个文件：

1. `server/index-服务入口.js:31-56`：`createServer` 怎么把 `/api/` 和静态文件分开。
2. `server/router-迷你路由.js:26-36` 和 `:69` 起：`add()` 怎么注册，`handle()` 怎么匹配 `:id`、解析 query 和 body、把 `HttpError` 转成 JSON。
3. `server/routes/products-商品接口.js:22-45`：接口层只把参数转交给 service。
4. `server/services/catalog-商品查询服务.js:51-108`：主函数 `query()`；配合 `:17-25` 的 `SORT_RULES` 和 `:37-49` 的 `toNumber()`。
5. `server/lib/store-JSON数据存储.js:41-67`：`read` / `write` / `update` 和内存缓存。
6. `server/lib/response-统一响应格式.js:17-50`：`HttpError`、`ok`、`fail` 如何统一出口。
7. 可选：`server/lib/static-静态文件服务.js:38` 起，看 HTML 和 SVG 是怎么返回的。

读法：把 Network 里那条请求的 Response 一直开着。每读一层，就回到 Response 确认这个字段是从哪一步冒出来的。

**过关标准**：能答出——URL 参数在哪一步变成对象；过滤顺序是不是“关键词 → 分类 → 价格 → 排序 → 分页”；`minPrice > maxPrice` 抛什么、谁把它变成 400；为什么 service 不接收 `res`。

小实验：用浏览器直接打开三个不同查询参数的接口地址，对照返回的 `total`。

## 第 3 站：后端写链路（90 min）

目标请求：`POST /api/orders`。先读购物车，再读下单。

1. `server/routes/cart-购物车接口.js:20-42` 和 `server/services/cart-购物车服务.js:36` 的 `getOrCreate()`、`:51` 的 `decorate()`、`:87` 的 `addItem()`、`:110` 的 `updateItem()`。
2. `server/routes/orders-订单接口.js:16-31`：四个接口的路由。
3. `server/services/orders-订单服务.js:45` 的 `create()`：校验库存、重算金额、生成单号、扣库存、清空购物车。
4. 同文件 `:29` 的 `orderId()`、`:37` 的 `shippingFeeFor()`、`:129` 的 `pay()`、`:143` 的 `cancel()`。
5. `server/lib/store-JSON数据存储.js:62` 的 `update()`：读—改—写是怎么串起来的。

**过关标准**：能答出——前端传来的价格会不会被采用；库存在哪一行被扣、下单失败会不会扣；订单号由什么组成；重复支付、取消已支付分别返回哪个错误码。

小实验：用 curl 或接口文档里的示例，下单一件 19 元的商品，确认运费是 12；再支付一次、重复支付一次，比较返回。

## 第 4 站：前端读链路（120 min）

目标：首页从空白到 8 张商品卡片。

1. `public/index-首页.html`：只看结构、区块顺序和 id，不看 class 细节。
2. `public/js/api-请求封装.js:47` 的 `request()`：拼查询串、12 秒超时、解析 JSON、`code !== 0` 抛 `ApiError`；再看 `:108` 的 `api` 分组。
3. `public/js/home-首页逻辑.js:75-101`：筛选条件怎么读写 URL；`:285` 的 `loadProducts()`：骨架屏、请求序号、渲染、分页；`:387` 的 `bindEvents()`。
4. `public/js/card-商品卡片.js:32` 的 `cardHtml()`：一张卡片由哪些字段拼成。
5. `public/js/ui-通用界面工具.js:21` 的 `escapeHtml()`、`:65` 的 `toast()`、`:96` 和 `:119` 的抽屉/弹窗、`:155` 的搜索框绑定。
6. CSS 只读三处：`base` 的变量、`layout` 的商品网格和断点、`components` 的卡片。

读法：在 DevTools 的 Sources 里给 `loadProducts()` 第一行打断点，刷新首页，单步看 state 怎么变成请求、响应怎么变成 DOM。

**过关标准**：能答出——为什么要先渲染骨架屏；`requestSeq` 解决什么问题；筛选条件为什么要写进地址栏；`escapeHtml` 防的是什么。

小实验：给首页加一个“评分最高”的排序选项，从 `<select>` 一路改到 service 的 `SORT_RULES`，确认能返回结果。

## 第 5 站：前端状态与下单（150 min）

目标：加购 → 抽屉 → 结算 → 订单页。

1. `public/js/store-购物车状态.js:23` 的 `CartStore`：`subscribe()`、`withBusy()`、`applyCart()`、`init()`、`add()`。
2. `public/js/cartdrawer-购物车抽屉.js:35-135`：模板、`render()`、`runAction()`、事件委托 `data-action`。
3. `public/js/checkout-结算下单.js:62-150`：打开弹窗、校验、`submitOrder()`、900ms 模拟支付、写 localStorage、跳结果页。
4. `public/product-商品详情页.html` 和 `public/js/product-详情页逻辑.js:87-245`：渲染、数量步进器、加入购物车、立即购买。
5. `public/orders-我的订单页.html` 和 `public/js/orders-订单页逻辑.js:143-320`：单笔查询、历史单、支付、取消、复制单号。
6. CSS 读 `components` 里的抽屉、购物车行、步进器、弹窗，再读 `pages` 里的订单卡片。

**过关标准**：能答出——加购后角标、抽屉、结算金额为什么同时更新；购物车为什么放服务端；下单后为什么 `resetLocal()`；刷新结果页为什么订单还在；重复点提交怎么防。

小实验：把包邮门槛从 99 改成 199，service 和结算弹窗两处都改，用一个 150 元的订单验证运费变成 12。

## 第 6 站：横向收口（60 min）

1. 五个 CSS 的加载顺序：base → layout → components → pages → extra，后一层覆盖前一层。
2. 断点 960 / 860 / 640 / 400 各自改了什么；用 390px 宽和 250% 缩放各看一次。
3. `scripts/gen-covers-生成商品封面.js`：`hash()`、`seeded()`、`buildSvg()`，理解“同一 id 每次生成同一张图”。
4. `docs/演示脚本-答辩怎么讲.md` 和 PDF 第 9–11 节：三条链路、演示顺序、排查清单。

**过关标准**：能解释 250% 缩放时靠什么不横向滚动；封面为什么不用外部图片。

## 第 7 站：自测与改动（120 min）

先合上书，再做三件事：

1. 白纸上画两条时序图：`GET /api/products` 和 `POST /api/orders`，从浏览器画到 JSON 文件。
2. 口头回答下面 10 个问题，卡住的记下来回到对应文件。
3. 做三个小改动，每个都走完整流程：新增一件商品、加一个排序、改一次运费门槛。

再做三个“破坏实验”，看错误怎么传到页面：

- 请求一个不存在的商品 id，看 404 页面还是错误块。
- 把购物车数量改到超过库存，看 409 和中文提示。
- 结算时填非法手机号，看前端校验拦在哪一步。

实验前先 `git checkout -b study`，做完可以丢弃，不污染 main。

## 依赖图（背下来）

```
后端：index → router → routes → services → lib/store → data/*.json
前端：html → 页面入口 js → api / store / ui / card → css
```

两条线都是单向的：页面入口只做组装，service 不碰 `req` / `res`，`lib` 不认识商品和订单。

## 每类文件读到什么程度

| 类型 | 第一遍读什么 | 可以先跳过 |
| --- | --- | --- |
| JSON 数据 | 一条记录的完整字段 | 其余 25 条 |
| routes | method、path、参数名 | 函数体细节 |
| services | 导出的主函数、抛错、返回结构 | 辅助函数 |
| lib | 导出清单和职责 | 具体实现 |
| HTML | 区块顺序和 id | class 和文案 |
| 页面 JS | `init()` → 事件 → 渲染函数 | 工具函数细节 |
| 通用 JS | 导出清单 + 一个主函数 | 边界分支 |
| CSS | 变量 → 布局 → 组件 → 页面 → 断点 | 单个阴影和圆角 |

## 三条不要

1. 不要按文件名从 A 读到 Z：先读链路，再补周边。
2. 不要第一遍读 `static-静态文件服务.js`、`404`、`gen-covers`、截图：它们是支线。
3. 不要边读边改：先读完一条链路，再动手实验。

## 十个自测问题

1. 浏览器打开首页，服务器返回的是什么？谁决定返回 HTML 还是 JSON？
2. `/api/products` 的查询参数在哪一步变成 `filters` 对象？
3. `pageSize` 超过 60 会发生什么？
4. 价格区间非法时返回哪个业务码？
5. 加购时库存不足返回什么？前端怎么显示？
6. 订单金额由谁计算？前端传的金额有用吗？
7. 订单号怎么生成？订单有哪几种状态？
8. 购物车数据存在哪里？刷新页面为什么还在？
9. 快速切换筛选时，旧请求比新请求晚返回会怎样？代码怎么处理？
10. 250% 缩放时，布局靠什么保证不横向溢出？

## 验收：什么叫“完全熟悉”

- 白纸上能画出两条链路，标出每一层负责什么。
- 任意指一个文件，能说出它的输入、输出、上游和下游。
- 10 个自测问题能答对 8 个以上。
- 三个小改动能独立完成，并且知道改完要验证哪几个页面。
- 能对着浏览器，把“搜索 → 加购 → 下单 → 订单结果”讲给一个没看过代码的人听。

这五条都做到，这个项目就真正属于你了。
