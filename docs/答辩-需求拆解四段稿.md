# 答辩四段稿 · 3.2–3.9 需求拆解

> 用法：每条按「原需求 → 拆解 → 取舍 → 验证」四段讲，控制在 40 秒，八条约 5 分钟。
> 只挑三条讲时，选 **3.4 搜索 / 3.7 购物车 / 3.9 响应式**——一条讲"状态"，一条讲"钱"，一条讲"底线"。

## 开口先说的方法论

> 我拆需求就问四个问题：这句话解决谁的什么问题；能拆成哪些**单独可验收**的点；这次**不做什么**；拿什么**证明**做到了。下面每条都按这个顺序。

## 3.2 导航与首页入口

**原需求**：导航、图标悬浮、推荐、列表、分类、搜索、购物车入口。——七个元素塞在一句话里，没说位置、优先级，也没说窄屏怎么办。

**拆解**
- 导航三项：首页 / 全部商品（完整目录）/ 我的订单；
- 购物车单独做成右上角常驻按钮，带角标；
- 首页顺序：Hero（26 件 / 25 件有货 / 6 个分类）→ 分类卡 → 本周热卖 8 件 → 编辑推荐 4 件 → 两个专题位；
- 筛选条、列表、分页独立到「全部商品」页：8 件一页，条件写进 URL；
- 悬浮态：图标上浮 2px 并轻微旋转，0.25s 过渡；
- 搜索框在 Hero 区，回车即搜。

**取舍**
- 购物车**不进导航**：导航回答"我在哪"，购物车是随时可做的动作，混在一起当前页就没法高亮了；独立按钮 + 角标，任何页面一键打开。
- 悬浮**只动图标、用 transform**：文字不跟着跳，也不触发重排；0.25s 是"看得见但不拖"的折中。
- 推荐**固定 4 件**：编辑推荐保持横向一排，热卖另取销量前 8，首屏不被工具条和长列表占满。

**验证**
- hover：图标动、文字不动；
- 加购后角标 +1，清空归零；
- 390px：导航文字隐藏、图标还在（这里修过一个 bug：原来整块 `display:none`，手机上直接没导航）。

## 3.3 商品卡片

**原需求**：卡片要有图片、名称、价格、简介、标签、分类。——只说"有"，没说缺字段怎么办、售罄长什么样。

**拆解**
- 六个字段齐全；价格为现价 + 划线原价；标签最多 2 个；
- 库存 0 走**售罄态**，在卡片上就能看出来；
- 整张卡片可点，进详情。

**取舍**
- 简介**两行截断**：卡片高度统一，网格不会参差；
- 分类做成**小字标签**而不是单独一行：省纵向空间，视觉上也更像"属性"；
- 售罄**前置到卡片**：不让用户点进详情才发现买不了。

**验证**
- 整页卡片高度对齐；
- 找到那件库存 0 的商品，看卡片和详情页分别怎么提示；
- 点卡片任意位置都能进详情。

---

## 3.4 关键词搜索

**原需求**：关键词搜索。——没说搜哪些字段、多久出结果、没结果怎么办。

**拆解**
- 匹配五个字段：名称、品牌、简介、标签、搜索词；
- 输入 **300ms 防抖**；
- 条件写进 URL（`?keyword=耳机`），刷新/分享可还原；
- 空态给「清除筛选」按钮，不是只写一句"没找到"；
- 每次请求带自增序号，只渲染最后一次结果。

**取舍**
- **服务端过滤**，不是把 26 件全拿回来在前端 `filter`：数据会涨、分页的 total 要准、URL 要能分享。
- 防抖 **300ms**：再短请求太密，再长手感发滞。
- 空态必须**可操作**："没找到"后面跟一个能点的按钮，而不是让用户自己想办法。
- 序号是为了防"慢请求覆盖快请求"——快速连打时旧结果不能盖新结果。

**验证**
- 搜「耳机」→ 5 件，地址栏带 keyword，刷新结果还在；
- 搜乱码 → 空态 + 清除筛选可点；
- 快速连打 → Network 里只渲染最后一次。

## 3.5 筛选与排序

**原需求**：至少一种筛选。——这是个下限要求，很容易做成"有就行"。

**拆解**
- 分类 + 价格区间，**可叠加**；
- 5 种排序：价格升/降、销量、评分、最新；
- 所有条件进 URL；
- 服务端按"关键词 → 分类 → 价格 → 排序 → 分页"依次算。

**取舍**
- 多条件**服务端一次算**：前端过滤会让分页数字对不上（总数和页数都是错的）。
- 排序做成**固定 5 档**：非法参数直接回落到默认，不用给自由输入做校验。
- 状态放 URL：返回键、刷新、复制链接都成立。

**验证**
- 关键词 + 分类 + 价格三条件叠加，看结果数、总数、分页是否自洽；
- 刷新后条件全在；
- 手改 URL 里的 sort 为非法值，看是否安全回落。

## 3.6 商品详情

**原需求**：商品详情。——没说什么算"完整"。

**拆解**
- 名称、图片、价格、原价与折扣、介绍、分类、库存、规格、数量、加购；
- 售罄禁用加购；
- 相关推荐 + 返回入口。

**取舍**
- 规格用**表格**而不是一段文字：扫读快，也方便对比；
- 数量在**加购前**选：避免"先加再改"多一步；
- 售罄**禁用按钮**而不是点了再报错：把错误挡在发生之前。

**验证**
- 数量改 2 → 抽屉里就是 2 件；
- 库存 0 的商品按钮不可点；
- 从详情返回列表，筛选条件还在。

---

## 3.7 侧拉购物车

**原需求**：侧拉购物车。——只说了形态，没说钱怎么算、买多少包邮。

**拆解**
- 添加、删除、改数量、单项小计、总金额、清空、免运费进度；
- 抽屉从右侧滑入，不跳页；
- 服务端返回整车快照，角标 / 抽屉 / 结算弹窗三处同步；
- 满 99 免运，否则 12 元运费。

**取舍**
- **购物车放服务端**：前端只传 `productId` 和数量，单价、小计、总价全由后端算——前端能改的只有数量，改不了钱。
- 用**抽屉**而不是整页：不打断"逛"的上下文，关掉还在原位。
- 免运做成**进度条**："还差 23 元"变成一个可见目标，比一行小字有用。

**验证**
- 控制台改价格再下单，金额不变（后端重算）；
- 换页回来同一辆车；
- 加到 99 以上看运费归零。

## 3.8 下单与结果页

**原需求**：下单与结果页。——没说什么算下单成功，失败怎么办。

**拆解**
- 表单校验（手机号）→ 创建订单（后端重算金额 + 运费）→ "支付中" 900ms → 结果页（订单号、明细、金额、时间、状态）→ 刷新可查；
- 重复支付返回 409，已取消订单不能再付；
- 未支付订单可取消。

**取舍**
- 支付做 **900ms 假等待**：真实支付也有这段等待，留出来才能讲清"支付中"这个状态。
- 订单号 `XM + 日期 + 6 位大写随机`：可读、可复制、不连续猜测。
- 结果页**按订单号查**：所以刷新、复制链接都能打开。
- 金额**一律后端算**：前端只展示，不做加法。

**验证**
- 手机号填错 → 前端拦住；
- 提交后看到"支付中…"，再跳结果页；
- 刷新结果页数据还在；
- 对已支付订单再点支付 → 409。

## 3.9 响应式

**原需求**：响应式。——两个字，没有标准。

**拆解**
- 三档 + 两个极端：桌面 / 平板 / 手机，外加 390px 宽和 250% 缩放；
- 判据只有一条：**没有横向滚动，关键操作都还在**；
- 网格 `repeat(auto-fill, minmax(min(100%, 240px), 1fr))` 自动降列；
- 断点 960 / 860 / 640 / 400，另有 900 / 760 / 520 做局部微调；
- 窄屏隐藏导航文字、保留图标；抽屉和弹窗 `max-width: 100%`。

**取舍**
- **自动降列**而不是给每个宽度写死列数：媒体查询少一半，中间宽度也不会出现空列。
- 断点取**内容开始挤**的位置，不取设备型号——iPhone 的宽度会变，内容不会。
- 250% 缩放本质是视口变窄，和响应式**共用一套规则**，不需要单独适配。

**验证**
- DevTools 390px 截图；
- 250% 缩放看有没有横向滚动条；
- console 无红字；导航图标还在、抽屉占满宽度。

## 一分钟电梯版

> 3.2–3.9 我没按考核点一条条做，而是先还原成一条用户路径：看到 → 搜到 → 筛到 → 看清 → 加购 → 算钱 → 下单 → 查单 → 换设备还能用。
> 每一步定三样东西：可验收的点、这次不做的边界、证明它成立的方法。
> 钱相关的判断都往后端推，交互相关的判断都往"少一步"上推，适配相关的判断都往"一套规则覆盖极端"上推。
> 最花时间的不是写页面，是决定哪些不做。

## 三个高频追问

**"这是不是照着考核点做的？"**
> 考核点是下限。对照表是拆完的结果，不是拆的过程；过程是先有用户路径，再回头对齐考核点，缺的补上。

**"哪条拆得最难？"**
> 3.8 下单。难的不是页面，是要假设用户不按剧本走：改价、重复支付、库存不足、支付中断，每一条都得有明确状态。

**"重做一次会改什么？"**
> 3.2 先定窄屏规则再写桌面。原来窄屏把导航整块隐藏，返工了一次。

## 讲的时候

- 别背稿，带一张表（需求 / 验收标准 / 证据），讲到哪指到哪；
- 每条讲完停半秒，把追问的机会留给对方；
- "我砍掉了什么"比"我做了什么"更值得讲。
