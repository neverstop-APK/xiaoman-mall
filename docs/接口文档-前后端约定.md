# 接口文档 · 前后端约定

> 这份文档回答三个问题：后端有哪些接口、每个接口收什么返回什么、出错时怎么查。
> 前端 `public/js/api-请求封装.js` 里的每个方法，都能在这里找到对应的接口。

## 一、基本约定

| 项目 | 约定 |
| --- | --- |
| 服务地址 | `http://127.0.0.1:3000`（端口可用环境变量 `PORT` 改） |
| 接口前缀 | 所有接口都以 `/api` 开头，其余路径交给静态文件服务 |
| 数据格式 | 请求体、响应体都是 JSON，`Content-Type: application/json` |
| 字符编码 | UTF-8 |
| 统一信封 | 成功 `{ code: 0, message: "ok", data: ... }`；失败 `{ code: 错误码, message: "中文原因", data: null }` |
| 金额单位 | 元，保留两位小数；运费满 99 元免，否则 12 元 |
| 购物车身份 | 首次请求购物车时服务端生成 `cart_xxxxxxxxxxxx`，前端存在 `localStorage` 的 `xm_cart_id` 里，之后每次请求都带上 |

### 怎么读一个响应

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "list": [],
    "total": 26
  }
}
```

- `code === 0` 表示业务成功，前端才会去读 `data`；
- `code !== 0` 表示业务失败，`message` 是可以直接给用户看的中文原因；
- HTTP 状态码同时也会变化（400 / 404 / 409 / 413 / 500），方便在 Network 面板一眼区分。

## 二、错误码表

| HTTP | code | 含义 | 典型场景 |
| --- | --- | --- | --- |
| 400 | 40000 | 请求体不是合法 JSON | 手动用 curl 测接口时漏了引号 |
| 400 | 40011 | 价格参数不是数字或超出范围 | `minPrice=abc`、负数 |
| 400 | 40012 | 最低价高于最高价 | `minPrice=500&maxPrice=100` |
| 400 | 40021 | 数量不合法 / 缺少 productId | 加购数量 0、100 |
| 400 | 40031 | 购物车是空的 | 空购物车点结算 |
| 404 | 40401 | 商品不存在 | 详情页地址栏 id 写错 |
| 404 | 40402 | 购物车里没有这件商品 | 重复删除同一项 |
| 404 | 40403 | 订单不存在 | 订单结果页 id 写错 |
| 404 | 40400 | 接口不存在 | 路径拼错，例如 `/api/product` |
| 409 | 40901 | 商品已售罄 | 库存 0 还加购 |
| 409 | 40902 | 库存不足 | 加购或下单数量超过库存 |
| 409 | 40903 | 订单已支付 | 重复调用支付接口 |
| 409 | 40904 | 订单已取消 | 取消后继续支付 |
| 409 | 40905 | 已支付订单不能取消 | 支付后再点取消 |
| 413 | 41301 | 请求体太大 | 超过 1MB |
| 500 | 50000 | 服务器内部错误 | 代码抛了未预期的异常 |

## 三、商品接口

### 3.1 商品列表

`GET /api/products`

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| keyword | string | 否 | 关键词，匹配名称、品牌、简介、标签、搜索词 |
| category | string | 否 | 分类 key，`all` 或省略表示全部 |
| minPrice | number | 否 | 最低价（含） |
| maxPrice | number | 否 | 最高价（含） |
| sort | string | 否 | `price-asc` / `price-desc` / `sales-desc` / `rating-desc` / `newest` |
| page | number | 否 | 页码，从 1 开始，默认 1 |
| pageSize | number | 否 | 每页条数，默认 12，最大 60 |

示例：

```
GET /api/products?keyword=耳机&maxPrice=99&sort=price-asc&page=1&pageSize=8
```

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "list": [
      {
        "id": "p02",
        "name": "听风 Studio 头戴降噪耳机",
        "brand": "听风",
        "category": "数码",
        "price": 699,
        "stock": 18,
        "rating": 4.7,
        "sales": 642,
        "tags": ["主动降噪", "40h续航"],
        "summary": "地铁里也能安静听歌",
        "cover": "/assets/products/p02-....svg"
      }
    ],
    "total": 1,
    "page": 1,
    "pageSize": 8,
    "totalPages": 1,
    "filters": { "keyword": "耳机", "category": "all", "minPrice": 0, "maxPrice": 99 },
    "sort": "price-asc"
  }
}
```

### 3.2 商品详情

`GET /api/products/:id`，例如 `/api/products/p02`。返回单个商品完整字段（含 `description`、`features`、`originalPrice`）。

失败：商品不存在时返回 `404 / 40401`。

### 3.3 分类列表

`GET /api/categories`，返回 6 个分类，每个分类带 `count`（该分类商品数）。

### 3.4 首页推荐

`GET /api/recommendations`，按销量取前 4 件。

### 3.5 相关推荐

`GET /api/products/:id/related`，同分类优先，取 4 件。

## 四、购物车接口

| 方法 | 路径 | 请求体 / 参数 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/cart` | `?cartId=xxx` | 读取购物车；没有 cartId 时新建一个空车 |
| POST | `/api/cart/items` | JSON `{ cartId, productId, quantity }` | 加购，已存在则累加 |
| PATCH | `/api/cart/items/:productId` | JSON `{ cartId, quantity }` | 改数量，`quantity: 0` 等价删除 |
| DELETE | `/api/cart/items/:productId` | `?cartId=xxx` | 删除单项 |
| DELETE | `/api/cart` | `?cartId=xxx` | 清空 |

购物车响应的 `data` 结构：

```json
{
  "id": "cart_8f3a1c9d20ab",
  "items": [
    {
      "productId": "p01",
      "name": "听风 Air One 真无线运动耳机",
      "price": 299,
      "quantity": 2,
      "stock": 42,
      "subtotal": 598,
      "soldOut": false
    }
  ],
  "totalQuantity": 2,
  "totalAmount": 598
}
```

> 注意：`totalAmount` 只算商品金额，不含运费；运费在订单接口里计算。

## 五、订单接口

| 方法 | 路径 | 请求体 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/orders` | `{ cartId, receiver: { name, phone, address }, remark }` | 创建订单，成功返回 201 |
| GET | `/api/orders/:id` | - | 订单详情，结果页用它渲染 |
| POST | `/api/orders/:id/pay` | - | 模拟支付，把状态改成已支付 |
| POST | `/api/orders/:id/cancel` | - | 取消未支付订单 |

创建订单时后端会做这些事（前端不需要重复计算）：

1. 用 `cartId` 读出购物车；空车直接 400；
2. 逐件检查商品是否还在、库存够不够；
3. 用**数据库里的单价**重新计算小计、商品金额、运费、应付金额；
4. 生成订单号 `XM + 日期 + 6 位大写十六进制`；
5. 扣库存、加销量、清空购物车、写入 `orders-订单数据.json`。

订单响应示例：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "id": "XM202610216D0378",
    "items": [
      { "productId": "p01", "name": "听风 Air One 真无线运动耳机", "price": 299, "quantity": 2, "subtotal": 598 }
    ],
    "goodsAmount": 598,
    "shippingFee": 0,
    "totalAmount": 598,
    "totalQuantity": 2,
    "status": "paid",
    "statusText": "已支付",
    "receiver": { "name": "王小满", "phone": "13800001234", "address": "浙江省杭州市西湖区小满路 1 号 3 幢 201" },
    "createdAt": "2026-10-21T07:37:12.000Z",
    "paidAt": "2026-10-21T07:37:13.000Z"
  }
}
```

## 六、出错了怎么查（面试会问）

1. 打开 DevTools 的 **Network** 面板，按 Fetch/XHR 过滤，找到失败的请求；
2. 看 **Status**：4xx 是前端传参问题，5xx 是后端代码问题；
3. 看 **Response** 里的 `code` 和 `message`，对照上面的错误码表；
4. 看 **Payload**（请求体）和 **Query String**，确认参数名、类型、大小写是否正确；
5. 如果是 404 且 Response 是 HTML，说明路径根本没进接口，检查前缀 `/api` 和拼写；
6. 如果是 `Failed to fetch`，检查服务是否启动、端口是否一致、是否被 CORS 拦截；
7. 服务端终端会打印 `[GET] /api/products 200 3ms`，用时间戳和前端请求对上。

## 七、前端封装对应关系

| 前端调用 | 实际请求 |
| --- | --- |
| `api.products.list(params)` | `GET /api/products?...` |
| `api.products.detail(id)` | `GET /api/products/:id` |
| `api.products.categories()` | `GET /api/categories` |
| `api.cart.add(productId, quantity)` | `POST /api/cart/items` |
| `api.cart.updateQuantity(productId, quantity)` | `PATCH /api/cart/items/:productId` |
| `api.orders.create(payload)` | `POST /api/orders` |
| `api.orders.pay(id)` | `POST /api/orders/:id/pay` |
