# 小满商城

一个能完整走通的购物网站：**逛 → 搜 → 筛 → 看详情 → 加购 → 改数量 → 结算 → 模拟支付 → 查订单**。

前端是原生 HTML / CSS / ES Module，后端是 Node.js 原生 `http`，26 件商品放在 JSON 文件里由后端读取。没有框架、没有构建步骤、没有 `npm install`。

> 在线地址：<https://chuangchengwujin.cn>（演示环境，数据可能被重置）
>
> 这是一个前端项目考核作品，不是生产系统。能做什么、没做什么，最后都写清楚了。

![小满商城首页](docs/screenshots/home.png)

## 先跑起来

需要 **Node.js 18 或更高版本**，然后三条命令：

```bash
git clone https://github.com/neverstop-APK/xiaoman-mall.git
cd xiaoman-mall
node server/index-服务入口.js
```

看到这行就成功了：

```text
小满商城已启动：http://127.0.0.1:3000
```

浏览器打开 <http://127.0.0.1:3000>。

Windows 也可以直接双击 `启动商城.bat`，它会检查 Node、启动服务并打开浏览器。关掉命令行窗口就停止服务。

没有默认账号，想试登录就自己注册一个。端口被占用时：

```powershell
$env:PORT=4000; node server/index-服务入口.js
```

打不开时先看三件事：命令行窗口是不是还开着；命令是不是在 `xiaoman-mall` 目录里执行；地址是不是 `http://127.0.0.1:3000`（不要直接双击 HTML 文件）。

## 第一次打开，建议这样逛

1. 首页看热卖和编辑推荐，点分类卡进入「全部商品」；
2. 在「全部商品」搜「耳机」，再点「数码」和「¥100–299」，看地址栏跟着变；
3. 进详情页，改数量，加入购物车，打开右侧抽屉改数量、看小计；
4. 去结算，先故意填错手机号看校验，再填对提交；支付是模拟的，会停 900ms；
5. 到「我的订单」看结果，注册账号后再下一单，订单会跟着账号走；
6. 点右下角「问问小满」，输入「500 元以内的键盘」，把第一件加购，再说「帮我下单」。

## 页面分工

| 页面 | 地址 | 负责什么 |
| --- | --- | --- |
| 首页 | `/` | Hero、分类入口、本周热卖 8 件、编辑推荐 4 件、两个专题位、最近看过 |
| 全部商品 | `/products-全部商品页.html` | 关键词、分类、价格区间、排序、分页；条件写进地址栏 |
| 商品详情 | `/product-商品详情页.html?id=p02` | 图片、价格、原价、库存、规格、介绍、相关推荐、加购 |

## 用了什么

| 层 | 选择 | 原因 |
| --- | --- | --- |
| 前端 | 原生 HTML5 + CSS3 + ES Module | 页面不多，想把请求、状态、DOM 更新这些基础写清楚；浏览器直接加载，没有构建步骤 |
| 后端 | Node.js 原生 `http` / `fs` / `path` / `crypto` | 零第三方依赖，克隆下来就能跑；也方便讲清一个请求怎么进、怎么出 |
| 数据 | JSON 文件 | 商品和分类是种子数据，购物车、订单、账号、会话运行时生成；适合演示，不适合高并发。另附一份可执行的初始 SQL，见下文 |
| 图片 | 脚本生成的 SVG 封面 | 不依赖外部图床，离线也能显示；不是商品实拍图 |
| 测试 | Node 自带 `node:test` + `assert` | 不装 Jest，测试代码也是项目的一部分 |

## 项目结构

```text

├─ server/                    后端，只在 Node 里运行
│  ├─ index-服务入口.js        创建 HTTP 服务，分发 /api 和静态文件
│  ├─ router-迷你路由.js       路径匹配、:id、query/body、统一错误
│  ├─ services/               业务规则：商品、购物车、订单、账号
│  ├─ routes/                 24 个接口的参数层
│  ├─ agent/                  AI 助手：编排、8 个工具、本地规则、大模型适配
│  ├─ lib/                    响应格式、JSON 存储、静态文件、Cookie 会话
│  ├─ data/                   商品/分类是种子；其余运行时生成
│  └─ sql/                    初始 SQL：8 张表 + 6 分类 + 26 商品
├─ public/                    前端，浏览器直接加载
│  ├─ 5 个 HTML 页面
│  ├─ css/                    8 个样式文件，按基础/布局/组件/页面/补充分层
│  └─ js/                     14 个 ES Module，一个文件一件事
├─ tests/                     46 条自动测试 + 30 条 AI 评测
├─ deploy/                    systemd、Nginx、Docker、环境变量模板
├─ docs/                      说明书、接口、阅读路线、演示、评测、截图
├─ scripts/                   生成商品封面、初始 SQL
├─ 启动商城.bat               Windows 双击启动
└─ package.json               启动、测试、评测命令
```

文件名前半段英文说明“这是什么”，后半段中文说明“它干什么”，例如 `cart-购物车服务.js`、`checkout-结算下单.js`。每个文件夹里还有一份 `说明-这个文件夹装什么.md`。

## 初始 SQL

仓库里附了一份初始 SQL：[`server/sql/init-初始化数据.sql`](server/sql/init-初始化数据.sql)。它是 SQLite 3 语法，包含 8 张表（分类、商品、用户、会话、购物车、购物车项、订单、订单项），以及 6 个分类、26 件商品的初始数据。

先说清楚：**这个项目真正运行时读的是 `server/data/` 里的 JSON，不是数据库**。这份 SQL 是为了满足提交要求，也方便以后换数据库时直接建库；它和 JSON 用的是同一份商品数据，数量对得上。

本地想验证，装过 SQLite 的话：

```bash
sqlite3 /tmp/xiaoman-mall.db < server/sql/init-初始化数据.sql
sqlite3 /tmp/xiaoman-mall.db "select count(*) from products;"   # 26
```

它会先删掉同名表再重建，别指向已经有数据的库。用户、会话、购物车、订单这几张表是空的，程序运行时会自己写入。换 MySQL 时要改主键类型和自增写法，文件开头有说明。

## 三条链路，先看懂这三条

### 1. 搜索 / 筛选：前端只传条件

```text
输入关键词或点分类
  → products-全部商品页逻辑.js 更新 state，写进地址栏
  → GET /api/products?keyword=...&category=...&page=1&pageSize=8
  → catalog-商品查询服务.js：关键词 → 分类 → 价格 → 排序 → 分页
  → 返回 { list, total, totalPages }
  → 页面渲染卡片、数量、分页器；没结果就显示空态
```

连续快速点击时用 `requestSeq` 防旧请求覆盖新结果。

### 2. 加购物车：状态放服务端

```text
点「加入购物车」
  → POST /api/cart/items { cartId, productId, quantity }
  → 服务端找到或新建购物车，校验库存，累加数量
  → 返回整辆车的最新快照
  → 顶栏角标、侧拉抽屉、结算弹窗一起更新
```

购物车放服务端，是为了下单时还能再校验一次库存和价格；前端改不了金额。

### 3. 下单：金额由服务端重算

```text
提交收货信息
  → POST /api/orders { cartId, receiver, remark }，不传金额
  → 服务端重读购物车、校验库存、按商品单价重算金额、生成订单号、扣库存、清空购物车
  → 201 返回订单
  → 前端调支付接口，停 900ms 模拟支付
  → 跳结果页，按订单号查询并渲染
```

订单号格式：`XM` + 年月日 + 6 位大写十六进制。

## 接口

所有接口统一返回：

```json
{ "code": 0, "message": "ok", "data": {} }
```

| 一组 | 数量 | 做什么 |
| --- | --- | --- |
| 商品 | 5 | 列表、详情、相关推荐、分类、首页推荐 |
| 购物车 | 5 | 读车、加购、改数量、删单项、清空 |
| 订单 | 5 | 创建、列表、详情、支付、取消 |
| 账号 | 4 | 注册、登录、退出、当前用户 |
| AI 助手 | 5 | 对话 SSE、确认下单、恢复会话、模式、工具清单 |

参数、响应示例、错误码表在 [接口文档](docs/接口文档-前后端约定.md)。

## 登录与 AI 助手

**登录态**：密码用 `scrypt` 加盐哈希；登录后只把 token 的 SHA-256 摘要存进会话表，原始 token 放 `HttpOnly` Cookie；订单带 `userId`，只能看自己的。未登录也能浏览、加购、下单，但生成的是游客订单，只能凭订单号查。

**AI 助手**：除 404 外的四个页面右下角都有「问问小满」。

- 两种模式：默认本地规则引擎，不联网也能演示；配置 `AGENT_API_KEY` 后切到 OpenAI 兼容的大模型模式；
- 8 个工具：搜索、详情、看购物车、加购、改数量、查订单、查单笔、创建订单；
- 写操作不直接执行：`create_order` 只生成待确认动作，用户在卡片里填收货信息、点确认后才真正建单；
- SSE 流式返回，刷新页面可以恢复会话；价格、库存、订单状态只来自工具结果。

本地规则引擎的 30 条评测全部通过，但它是规则基线，不等同于大模型效果；模型对比需要 API Key，报告里没有冒充跑过。

## 部署

`deploy/` 里已经准备好 systemd、Nginx、Docker 和环境变量模板。步骤概要：

1. 服务器装 Node.js 18+，项目放到 `/opt/xiaoman-mall`（systemd 示例的 `WorkingDirectory` 写的是 `/opt/xiaoman-mall/xiaoman-mall`，按你的实际目录改）；
2. 用 `systemd` 托管，非 root、开机自启、崩溃拉起；
3. Nginx 反代 `127.0.0.1:3000`，配置 HTTPS；SSE 要关 `proxy_buffering`。线上这台机器 3000 已被别的服务占用，所以小满用 `PORT=3100`，反代端口跟着改；
4. API Key 只放服务器环境变量文件，权限 600，不进仓库。

境内服务器绑定正式域名通常要先完成 ICP 备案，境外服务器不需要。完整步骤见 [部署说明](docs/部署-服务器与域名.md)。

> 在线演示：<https://chuangchengwujin.cn>。演示数据可能被重置；这台机器的 HTTPS 证书是 DNS-01 手动签发的，到期前要按部署文档续期。

## AI Coding Process

这个项目确实大量用了 AI 辅助，但不是“让 AI 写完就算”：

1. **先把验收点拆成清单**：3.1–3.9、接口、数据、账号、9.1–9.8，做一项勾一项；
2. **先接口后页面**：数据结构 → service → route → 接口文档 → 页面，页面里不写业务规则；
3. **一次只改一件事**：改完立刻跑对应测试，不把多个行为混在一次修改里；
4. **让 AI 找反例**：追问“最可能破坏哪个已有功能”“给我三个会失败的用户输入”；
5. **人工验收**：无头浏览器截图看排版，Network 看状态码，终端日志对时间；AI 说“完成”不等于页面对；
6. **文档跟着代码走**：新增接口就更新接口文档，新增行为就补评测用例。

完整记录在 [Prompt Engineering 与 AI 协作](docs/Prompt-Engineering与AI协作.md)。

## 已知边界

- 数据存 JSON 文件，单进程读写，适合演示，不适合高并发；没有数据库事务；
- 支付是模拟的，不接真实支付；没有商品管理后台、图片上传、邮箱验证、多租户；
- AI 本地模式是规则引擎，不是大模型；大模型模式需要 API Key，模型对比还没实跑；
- 商品封面是脚本生成的 SVG，不是实拍图；
- 在线 Demo 是演示环境，数据可能被重置；AI 默认走本地规则，不调用外部模型。
