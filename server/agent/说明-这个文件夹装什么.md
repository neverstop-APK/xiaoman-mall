# server/agent/：AI 购物助手

**一句话**：把用户的一句自然语言，变成“查商品、改购物车、生成待确认订单”的工具调用。

## 装了什么
- `agent-购物助手.js`：编排层。负责选 local / llm 模式、组织系统提示词、跑“模型 → 工具 → 模型”的循环、收集 Trace、处理确认下单；`chat()` 从第 68 行开始，`confirm()` 在第 182 行。
- `tools-工具集.js`：8 个工具的“说明书 + 执行器”。工具名是 `search_products`、`get_product`、`view_cart`、`add_to_cart`、`update_cart_quantity`、`list_my_orders`、`get_order`、`create_order`；`DEFINITIONS` 从第 27 行开始，`execute()` 在第 403 行。
- `localbrain-本地规则引擎.js`：没有配置大模型时的本地实现。用规则识别意图、抽取预算/品类/品牌、处理“便宜一点”这类多轮约束；`run()` 从第 602 行开始。
- `llm-大模型适配器.js`：对接 OpenAI 兼容的 `/chat/completions`，把工具定义转成 function calling，支持流式增量；`streamChat()` 第 71 行，`run()` 第 176 行。调用失败会回退到本地引擎。
- `conversation-会话存储.js`：保存每个会话的消息、记忆槽位和待确认动作；`getOrCreate()` 第 72 行，`append()` 第 104 行。

## 和谁配合
`routes/agent-购物助手接口.js` 收到请求后调 `agent.chat()`；agent 再调 `tools.execute()`；工具内部复用 `services/` 里的商品、购物车、订单服务——所以 AI 和网页用的是同一套业务规则，不会算出两个价格。

## 读法
先看 `tools-工具集.js` 最上面的 `DEFINITIONS`，那是模型能看到的“能力清单”；再看 `agent-购物助手.js` 的 `chat()`，理解一轮对话怎样变成工具调用；最后看 `localbrain-本地规则引擎.js`，它用同一套工具做了不依赖网络的兜底。

## 注意
- 助手不会直接付款：`create_order` 只生成待确认订单，必须再调 `/api/agent/confirm` 才真正落单。
- 没有 API Key 也能演示，此时 `mode()` 返回 `local`；配了 Key 才走大模型。
- 每次调用的输入、工具、耗时写在 `server/data/agent-traces.jsonl`，排查“它为什么这么答”先看这里。
