# server/services/：业务规则层

**一句话**：这个项目“算错了会出事”的逻辑都在这里，和 HTTP 无关。

## 装了什么
- `catalog-商品查询服务.js`：关键词、分类、价格、排序、分页、分类计数、首页推荐、相关商品。
- `cart-购物车服务.js`：创建/查找购物车、加购累加、改数量、删除、清空、算单项小计与总金额、校验库存。
- `orders-订单服务.js`：重算金额与运费（满 99 免运，否则 12 元）、生成订单号、扣库存、加销量、清空购物车、支付/取消、按用户查订单（`listByUser()` 第 178 行）；订单带 `userId`，取消已支付订单会回滚库存。
- `auth-用户认证服务.js`：注册、登录、退出、按 token 查用户；密码用 `crypto.scryptSync` 加盐哈希，会话 7 天，对外只暴露 `publicUser()` 的字段。

## 和谁配合
被 `routes/` 调用，也被 `server/agent/tools-工具集.js` 调用；只依赖 `lib/` 和 `data/`，不碰 `req` / `res`。所以网页、AI 助手、自动测试用的是同一套规则。

## 读法
先看 catalog 的 `query()`，再看 cart 的 `addItem()`，然后 orders 的 `create()`，最后 auth 的 `register()` / `login()`。

## 注意
价格、库存、订单归属只在这里判断；接口层就算传了假价格也不会被采信。
