# server/data/：JSON 数据表

**一句话**：这个项目的“数据库”，一张表就是一个 JSON 文件，第一次写入时自动创建。

## 装了什么
- `products-商品数据.json`：26 件商品的固定数据，含 id、名称、品牌、分类、价格、库存、销量、标签、封面等。
- `categories-商品分类.json`：6 个分类（数码、家居、文具、户外、服饰、配件）及数量说明。
- `carts-购物车数据.json`：运行时生成，一辆购物车一条记录。
- `orders-订单数据.json`：运行时生成，一笔订单一条记录；没有下过单时文件可能不存在。
- `users-用户数据.json`：注册用户，密码只存 scrypt 哈希和盐，不存明文。
- `sessions-用户会话.json`：登录令牌的哈希、所属用户、过期时间。
- `conversations-助手会话.json`：AI 助手的消息、记忆槽位、待确认动作。
- `agent-traces.jsonl`：AI 每次调用的输入、工具、耗时，一行一条，便于排查和评测。

## 和谁配合
`lib/store-JSON数据存储.js` 通过表名映射到文件名；`services/` 只认表名，不关心文件叫什么。

## 注意
- 商品和分类是随项目提供的种子数据；其余都是运行时数据，已写进 `.gitignore`。
- 想得到干净的演示环境：停服务，把 carts / orders / users / sessions / conversations 清成 `[]`，删掉 `agent-traces.jsonl`，再启动。
- 跑测试时用 `XM_DATA_DIR` 指向临时目录，不会污染这里的演示数据。
- 服务运行时会缓存，手改文件后要重启才读得到。
